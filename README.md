# Alpine Waiter Web — ব্যবহারের নির্দেশিকা

React Native CLI অ্যাপের একই বাংলা ডিজাইন ও একই staff API ব্যবহার করে তৈরি Next.js + Tailwind CSS ওয়েব অ্যাপ। আলাদা ডাটাবেজ বা আলাদা কর্মীর অ্যাকাউন্ট তৈরি হয় না।

## কোথায় আছে

`D:\alppine-restrent\alpine-waiter-web`

## প্রথমবার চালানো

Node.js 22 এবং চালু লোকাল MongoDB/Alpine API প্রয়োজন।

```powershell
cd D:\alppine-restrent\alpine-waiter-web
npm install
npm run dev
```

ল্যাপটপে: http://localhost:3200

একই Wi-Fi-তে ফোনে: http://192.168.0.102:3200

ফোনে ওয়েবের পোর্ট 3200 খুলবেন। Android APK-এর server settings-এ API-এর পোর্ট 4200 আগের মতো থাকবে। IP বদলালে নিচের সেটিংও বদলান।

## সার্ভারের সেটিং

`.env.example` একটি নমুনা; আসল সেটিং `.env.local`-এ:

```env
WAITER_API_URL=http://127.0.0.1:4100
WAITER_REALTIME_URL=http://192.168.0.102:4200
```

- `WAITER_API_URL`: Next.js সার্ভার থেকে ব্যাকএন্ডে যাওয়ার ঠিকানা। ব্রাউজারের ফরম দিয়ে বাইরের API সার্ভার বদলানো যায় না।
- `WAITER_REALTIME_URL`: ফোন/ব্রাউজার থেকে সরাসরি Socket.IO সংযোগের ঠিকানা।
- API-এর `.env`-এ `WAITER_LAN_HOST=192.168.0.102` ও `WAITER_LAN_PORT=4200` থাকতে হবে।
- API টার্মিনালে LOCAL DATABASE এবং LAN gateway ready দেখুন। Windows-এর Private network-এ প্রয়োজন হলে 3200 ও 4200 পোর্টের অনুমতি দিন।
- সেটিং বদলালে সংশ্লিষ্ট সার্ভার আবার চালু করুন।

প্রোডাকশনে একই দুই সেটিং HTTPS backend URL-এ পরিবর্তন করবেন। ওয়েব সাইটও HTTPS-এ চালাবেন। কোনো MongoDB URI, Firebase secret বা JWT secret এই প্রজেক্টের ব্রাউজার কনফিগে দেবেন না।

## অ্যাডমিন থেকে প্রস্তুতি

1. মেনু আইটেমের বাংলা নাম, ইউনিক কোড, দাম, বিক্রির অবস্থা ও কিচেন নির্ধারণ করুন।
2. টেবিল তৈরি করুন এবং ওয়েটারের টেবিল বরাদ্দ করুন।
3. প্রত্যেক অপারেটরের রোল ও কিচেন স্টেশন বরাদ্দ করুন।
4. গণনাভিত্তিক স্টক চালু থাকলে `Stock & daily closing` থেকে দিনের প্রস্তুত খাবারের স্টক খুলুন। `ক্রয় ও স্টোর` এর সঙ্গে এই বিক্রির স্টক আলাদা।
5. একই বিদ্যমান মোবাইল নম্বর/ইমেইল ও অ্যাডমিনের দেওয়া পাসওয়ার্ডে ওয়েব বা Android-এ লগইন করুন।

## অর্ডার নেওয়া

1. টেবিল বাছুন বা নতুন পার্সেল অর্ডার নিন। ব্যস্ত টেবিলে আগের অর্ডারে আরও খাবার যোগ বা নতুন আলাদা অর্ডার করা যায়।
2. নাম, বাংলা/ইংরেজি বা কোড দিয়ে সার্চ করুন; ক্যাটাগরি বাছুন। +/− দিয়ে খাবার যোগ করুন।
3. কার্টে গিয়ে এখানে খাবেন/পার্সেল ঠিক করুন। একই খাবারের কিছু অংশও পার্সেল করা যায়। কাস্টমারের তথ্য, প্যাকিং চার্জ ও রান্নার নির্দেশনা ঐচ্ছিক।
4. পরিমাণ ও মোট টাকা মিলিয়ে কিচেনে পাঠান। আলাদা কিচেনে আলাদা KOT তৈরি হবে। আসল প্রিন্টের জন্য API-এর printer worker ও বাস্তব printer configuration প্রয়োজন।
5. নেটওয়ার্কে নিশ্চয়তা না পেলে একই সেভ করা অনুরোধ আবার পাঠান। অনিশ্চিত অবস্থায় কার্ট সম্পাদনা বন্ধ থাকে। কোনো বিকল্প নতুন request দিয়ে আগের অনুরোধ উপেক্ষা করবেন না।
6. অর্ডার/KOT পেজ থেকে অবস্থা দেখুন বা ওই অর্ডারে খাবার যোগ করুন। বিল সংগ্রহ অ্যাডমিনে আগের মতো হবে।

## কিচেন ও পরিবেশন

- অপারেটর লগইন করলে শুধু বরাদ্দ করা স্টেশনের কাজ দেখা যায়। গ্রহণ → প্রস্তুত / প্যাকিং সম্পন্ন। আংশিক প্রস্তুত পরিমাণও দেওয়া যায়।
- প্রস্তুত হলে সংশ্লিষ্ট ওয়েটারের খবরের তালিকায় খবর আসে। ওয়েটার প্রস্তুতি পেজে সংগ্রহ ও কাস্টমারকে সার্ভ/হস্তান্তর নিশ্চিত করেন।
- মোবাইল বা ওয়েব থেকে পরিবর্তন একই API/Socket.IO event দিয়ে অন্য ডিভাইসে পৌঁছায়। সংযোগ ফিরে আসা/ট্যাব খোলা এবং fallback polling-এ ডাটা পুনরায় মেলে।

## ভয়েস ও ব্রাউজার নোটিফিকেশন

- ভয়েস সার্চে বাংলা বললে নাম বা কোড বসে; ভয়েস অর্ডারে আগে পরিমাণসহ একটি review তালিকা আসে। নিশ্চিত না করে অর্ডার পাঠানো হয় না। একই মেনুর বাংলা/ইংরেজি নাম ও aliases দিয়ে মিল হয়; Gemini/API key লাগে না।
- ব্রাউজারের speech recognition সব ব্রাউজারে নেই। মাইক্রোফোন সাধারণত HTTPS বা localhost-এ চলে। ফোনের plain HTTP LAN URL-এ ভয়েস না চললে সাধারণ সার্চ, টাইপ করে voice review এবং বোতামের অর্ডার ব্যবহার করুন। সমর্থিত ব্রাউজার তার নিজস্ব speech service ব্যবহার করতে পারে।
- খবরের তালিকা সাধারণ LAN HTTP-তেও চলে। Browser notification permission HTTPS/localhost-এ দেওয়া যায়; ট্যাব চলমান থাকতে হবে। ব্রাউজার পুরো বন্ধ থাকলে background Web Push এই সংস্করণে কনফিগার করা হয়নি। Android FCM-এর আগের ব্যবস্থা অপরিবর্তিত।

## সেশন ও কার্ট

- ওয়েব লগইন HttpOnly cookie-তে থাকে। Socket.IO-এর জন্য টোকেন শুধু চলমান পেজের memory-তে আসে; localStorage-এ পাসওয়ার্ড বা token রাখা হয় না।
- না-পাঠানো কার্ট ও pending request ID ওই ব্রাউজারে কর্মী ও সার্ভার অনুযায়ী সেভ হয়। অন্য ফোনের draft নিজে থেকে আসে না; পাঠানো অর্ডারই সব ডিভাইসে sync হয়।
- ব্রাউজারের storage বন্ধ থাকলে নিরাপদে pending order রাখা যাবে না। storage/সাইটের ডাটা মুছবার আগে অনিশ্চিত অর্ডার মিলিয়ে নিন।
- ভূমিকা, টেবিল, স্টেশন ও অর্ডারের মালিকানা সব মূল API যাচাই করে। ওয়েব UI লুকানোই একমাত্র নিরাপত্তা নয়।

## যাচাই ও প্রোডাকশন বিল্ড

```powershell
npm run typecheck
npm test
npm run build
npm start
```

`npm start`-এর আগে `npm run build` সম্পন্ন করুন। dev এবং production build একই `.next` ফোল্ডার ব্যবহার করে; একই সময়ে একই প্রজেক্টে দুটো চালাবেন না।

## ফাইলের গঠন

- `app/api`: staff-only session/proxy; server থেকে বিদ্যমান Alpine API-তে যোগাযোগ।
- `components/screens`, `components/cart`, `components/voice`, `components/operations`: আলাদা ছোট UI component।
- `hooks`: অর্ডার, realtime ও speech controller।
- `services`: browser draft storage ও same-origin transport।
- `utils`/`types`: Android-এর সঙ্গে একই খাবার matching, parcel ও domain rules-এর ওয়েব কপি। ভবিষ্যতে এই নিয়ম বদলালে দুই প্রজেক্টের contract/tests একসঙ্গে আপডেট করুন।
